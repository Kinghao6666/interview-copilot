## 一、Primary Persona（核心用户画像）

### 张晨 — 计算机专业大四学生

**基本信息：**
- 年龄：22 岁
- 学校：普通 211 本科，计算机科学与技术专业
- 目标：秋招拿到互联网大厂后端开发 offer

**技能水平：**
- 掌握 C++、Python、Java 基础
- 学过数据结构、操作系统、计算机网络、数据库
- 做过 2-3 个课程项目，但缺乏实际工程经验
- 刷过 100+ LeetCode 题目

**痛点与目标：**
1. **面试焦虑** — 不知道自己简历上的技能会被问到什么深度
2. **缺乏反馈** — 模拟面试找同学帮忙，但同学也不专业，给不出有效建议
3. **时间紧迫** — 秋招只有 2-3 个月，需要快速定位薄弱环节并针对性提升
4. **表达能力弱** — 技术懂，但不知道怎么说得清楚、有条理

**使用场景：**
- 投递简历前：用 AI 面试助手测试简历上的技能点是否扎实
- 面试前一周：针对目标公司 JD 做专项模拟，熟悉可能被问到的问题
- 面试后复盘：对比 AI 评分和实际面试表现，找出差距

**成功标准：**
- 能在 30 分钟内完成一次完整模拟面试
- 得到具体的改进建议（不是泛泛而谈）
- 看到自己的进步（历史记录对比）

---

## 二、核心价值主张

**一句话价值：** 让校招求职者在 30 分钟内发现面试薄弱环节，获得针对性改进建议。

**价值循环：**
1. **输入** — 上传 JD + 简历
2. **行动** — 完成 25-30 分钟模拟面试（4 个部分）
3. **反馈** — 每道题即时评分 + 改进建议
4. **奖励** — 生成详细复盘报告（雷达图、技能短板、行动建议）
5. **成长** — 历史记录对比，看到进步曲线

**与竞品的差异：**
- 不是通用的"AI 聊天机器人"，而是**结构化的面试流程**
- 不是"随机问问题"，而是**基于简历技能精准匹配题目**
- 不是"给个总分就完事"，而是**4 维度细化评分 + 具体改进建议**

## 三、用户流程设计

### 3.1 完整用户旅程

```
[注册/登录] → [上传 JD + 简历] → [系统解析 + 匹配度评估] → [开始模拟面试]
    ↓
[Part 1: 自我介绍] → [即时评分 + 建议]
    ↓
[Part 2: 技能测试] → [每题即时评分 + 建议]
    ↓
[Part 3: 场景题] → [即时评分 + 建议]
    ↓
[Part 4: 反问环节] → [即时评分 + 建议]
    ↓
[生成复盘报告] → [查看历史记录] → [再次练习]
```

### 3.2 首次体验（Onboarding）— 前 60 秒

**目标：** 让用户在 60 秒内理解产品价值，并完成第一步操作。

**流程设计：**

**0-10 秒：价值感知**
- 落地页标题："30 分钟发现你的面试薄弱环节"
- 副标题："AI 模拟真实校招面试，给出针对性改进建议"
- 视觉：黑金配色 + 雷达图动画 + 实时评分演示

**10-30 秒：快速注册**
- 邮箱注册（无需验证码，直接发送登录链接）
- 或 GitHub OAuth 一键登录
- 无需填写其他信息，降低摩擦

**30-60 秒：立即行动**
- 注册后直接跳转到"上传 JD + 简历"页面
- 提供示例 JD 和简历模板（一键填充）
- 明确提示："上传后 10 秒内生成面试题目"

**可供性设计：**
- 上传区域：拖拽 + 点击上传，支持 PDF/TXT/DOCX
- 进度提示：解析中 → 匹配技能 → 生成题目（进度条 + 文字说明）
- 即时反馈：上传成功后立即显示"匹配到 8 项技能，生成 12 道题目"

### 3.3 核心使用循环（模拟面试）

**Part 1: 自我介绍（3-5 分钟）**

**界面设计：**
- 左侧：题目显示区（"请做一个 3 分钟的自我介绍"）
- 中间：文本输入框（支持 Markdown）
- 右侧：实时提示（"建议包含：教育背景、技术栈、项目经验、求职意向"）
- 底部：提交按钮 + 计时器

**交互流程：**
1. 用户开始输入 → 计时器启动
2. 用户点击"提交" → 系统评分（3-5 秒）
3. 显示评分结果（0-100 分）+ 4 维度雷达图
4. 显示改进建议（1-2 句话，具体可执行）
5. 用户点击"下一题" → 进入 Part 2

**Part 2: 技能测试（10-12 分钟）**

**题目生成逻辑：**
- 从简历解析出的技能列表中随机抽取 3-4 项
- 每项技能出 2-3 道题（共 8-10 道题）
- 题目难度：中等偏易（本科/研究生校招水平）
- 题型：概念理解、原理解释、简单应用

**示例题目映射：**

| 技能 | 题目示例 |
|------|----------|
| C/C++ | 1. 指针和引用的区别是什么？<br>2. 虚函数的实现原理是什么？<br>3. STL 中 vector 和 list 的使用场景有何不同？ |
| Python | 1. 什么是 GIL？它对多线程有什么影响？<br>2. 装饰器的作用是什么？请举例说明。<br>3. 列表推导式和生成器表达式的区别？ |
| 数据结构 | 1. 快速排序的时间复杂度是多少？最坏情况是什么？<br>2. 哈希表如何解决冲突？<br>3. 二叉搜索树和平衡二叉树的区别？ |
| 操作系统 | 1. 进程和线程的区别是什么？<br>2. 死锁的四个必要条件是什么？<br>3. 虚拟内存的作用是什么？ |
| 计算机网络 | 1. TCP 和 UDP 的区别是什么？<br>2. HTTP 状态码 200、301、404、500 分别表示什么？<br>3. 三次握手的过程是什么？ |
| 数据库 | 1. 索引的作用是什么？什么时候不应该建索引？<br>2. 事务的 ACID 特性是什么？<br>3. 如何优化慢查询？ |

**界面设计：**
- 顶部：进度条（"第 3/10 题"）
- 左侧：题目显示
- 中间：文本输入框
- 右侧：参考提示（"建议回答时长：1-2 分钟"）
- 底部：提交 + 跳过按钮

**Part 3: 场景题（8-10 分钟）**

**题目生成逻辑：**
- 根据 JD 岗位类型选择场景题
- 后端开发 → 系统设计、性能优化、问题排查
- 前端开发 → 组件设计、性能优化、兼容性问题
- 算法岗 → 模型选择、特征工程、调参经验

**示例题目：**
1. "设计一个短链接服务，需要考虑哪些问题？"
2. "线上服务突然变慢，如何排查？"
3. "如何设计一个高并发秒杀系统？"
4. "如何实现一个前端路由？"
5. "如何优化一个加载缓慢的网页？"

**评分维度：**
- 思路清晰（30%）— 是否有结构化的分析框架
- 考虑全面（30%）— 是否覆盖关键技术点
- 技术深度（20%）— 是否涉及底层原理
- 实际可行（20%）— 方案是否可落地

**Part 4: 反问环节（2-3 分钟）**

**题目：** "你有什么问题想问面试官？"

**评分标准：**
- 问题质量（50%）— 是否体现对公司/岗位的了解
- 职业规划（30%）— 是否体现长期发展意识
- 表达清晰（20%）— 问题是否具体、有针对性

**好问题示例：**
- "团队目前的技术栈是什么？有哪些技术挑战？"
- "新人入职后的成长路径是怎样的？"
- "团队的工作氛围和协作方式是怎样的？"

**差问题示例：**
- "公司有什么福利？"（过于关注待遇）
- "加班多吗？"（负面印象）
- "没有问题"（缺乏主动性）

### 3.4 复盘报告生成

**报告结构：**

1. **总分 + 各部分得分**
   - 总分：0-100 分
   - 自我介绍：XX 分
   - 技能测试：XX 分
   - 场景题：XX 分
   - 反问环节：XX 分
   - 雷达图可视化

2. **单题得分 + 参考答案**
   - 每道题的得分（0-100 分）
   - 用户回答（原文）
   - 参考答案（AI 生成）
   - 改进建议（1-2 句话）

3. **技能短板分析**
   - 哪些技能得分低于 60 分
   - 哪些技能需要重点加强
   - 推荐学习资源（文章/视频链接）

4. **改进建议（3-5 条）**
   - 具体、可执行的行动项
   - 示例：
     - "加强对 TCP 三次握手的理解，建议阅读《计算机网络：自顶向下方法》第 3 章"
     - "回答场景题时，先列出关键技术点，再逐一展开，避免跳跃式思维"
     - "自我介绍中突出项目亮点，用数据说话（如'优化后性能提升 30%'）"

5. **历史记录对比**
   - 如果有历史记录，显示进步曲线
   - 哪些技能有提升，哪些还需加强

**导出功能：**
- 支持导出为 PDF（用于打印复习）
- 支持分享链接（用于求职简历附件）

## 四、面试题目生成逻辑

### 4.1 简历解析

**输入：** 用户上传的简历（PDF/TXT/DOCX）

**解析目标：**
1. 提取技能关键词（编程语言、框架、工具）
2. 提取项目经验（项目名称、技术栈、职责）
3. 提取教育背景（学校、专业、学历）

**技术实现：**
- 使用 OpenAI GPT-5.3-codex 的文本提取能力
- Prompt 示例：
  ```
  请从以下简历中提取：
  1. 技能列表（编程语言、框架、工具）
  2. 项目经验（项目名称、技术栈、职责）
  3. 教育背景（学校、专业、学历）

  输出格式：JSON
  ```

**输出示例：**
```json
{
  "skills": ["C++", "Python", "数据结构", "操作系统", "计算机网络", "MySQL"],
  "projects": [
    {
      "name": "在线购物系统",
      "tech_stack": ["Spring Boot", "MySQL", "Redis"],
      "role": "后端开发"
    }
  ],
  "education": {
    "school": "XX 大学",
    "major": "计算机科学与技术",
    "degree": "本科"
  }
}
```

### 4.2 JD 解析

**输入：** 用户上传的 JD（文本）

**解析目标：**
1. 岗位类型（后端/前端/算法/测试等）
2. 技能要求（必备技能 + 加分项）
3. 工作内容（核心职责）

**输出示例：**
```json
{
  "position": "后端开发工程师",
  "required_skills": ["Java", "Spring Boot", "MySQL", "Redis"],
  "preferred_skills": ["分布式系统", "高并发"],
  "responsibilities": ["负责后端服务开发", "优化系统性能"]
}
```

### 4.3 题目匹配逻辑

**Step 1: 技能匹配**
- 计算简历技能与 JD 要求的交集
- 匹配度 = 交集技能数 / JD 要求技能数

**Step 2: 题目抽取**
- 从题库中抽取与匹配技能相关的题目
- 优先抽取 JD 必备技能的题目
- 随机抽取部分加分项技能的题目

**Step 3: 难度调整**
- 根据用户学历（本科/研究生）调整题目难度
- 本科：中等偏易
- 研究生：中等偏难

**题库结构：**
```json
{
  "skill": "C++",
  "questions": [
    {
      "id": "cpp_001",
      "question": "指针和引用的区别是什么？",
      "difficulty": "easy",
      "tags": ["基础概念"],
      "reference_answer": "指针是一个变量，存储的是地址；引用是别名，不占用额外内存..."
    }
  ]
}
```

## 五、评分标准设计

### 5.1 评分维度（4 个维度）

**1. 技术准确性（40%）**
- 定义：回答的技术内容是否正确
- 评分标准：
  - 90-100 分：完全正确，无明显错误
  - 70-89 分：基本正确，有少量细节错误
  - 50-69 分：部分正确，有明显错误
  - 0-49 分：大部分错误或答非所问

**2. 表达清晰度（30%）**
- 定义：回答是否清晰、易懂
- 评分标准：
  - 90-100 分：逻辑清晰，层次分明，无歧义
  - 70-89 分：基本清晰，有少量表达不够精确
  - 50-69 分：表达混乱，逻辑跳跃
  - 0-49 分：完全看不懂在说什么

**3. 结构完整性（20%）**
- 定义：回答是否有结构，是否覆盖关键点
- 评分标准：
  - 90-100 分：结构完整，覆盖所有关键点
  - 70-89 分：结构基本完整，遗漏少量关键点
  - 50-69 分：结构不完整，遗漏多个关键点
  - 0-49 分：无结构，想到哪说到哪

**4. 深度与广度（10%）**
- 定义：回答是否有深度，是否涉及底层原理
- 评分标准：
  - 90-100 分：有深度，涉及底层原理或实际应用
  - 70-89 分：有一定深度，但不够深入
  - 50-69 分：停留在表面，缺乏深度
  - 0-49 分：完全没有深度

### 5.2 评分实现

**技术方案：**
- 使用 OpenAI GPT-5.3-codex 的评分能力
- Prompt 示例：
  ```
  请对以下面试回答进行评分（0-100 分），并给出 4 个维度的得分：

  题目：{question}
  参考答案：{reference_answer}
  用户回答：{user_answer}

  评分维度：
  1. 技术准确性（40%）
  2. 表达清晰度（30%）
  3. 结构完整性（20%）
  4. 深度与广度（10%）

  输出格式：JSON
  {
    "total_score": 85,
    "accuracy": 90,
    "clarity": 80,
    "structure": 85,
    "depth": 75,
    "feedback": "回答基本正确，但可以更深入地解释虚函数表的实现原理。"
  }
  ```

### 5.3 改进建议生成

**原则：**
- 具体、可执行（不说"需要加强"，而说"建议阅读 XX 资料"）
- 针对性强（针对用户的具体问题）
- 正面鼓励（先肯定优点，再指出不足）

**示例：**
- ❌ 差建议："需要加强对操作系统的理解"
- ✅ 好建议："对进程和线程的区别理解正确，但可以进一步解释线程共享哪些资源。建议阅读《操作系统概念》第 4 章。"

## 六、可用性检查清单

### 6.1 新手友好性

- [ ] 首次使用无需阅读文档即可上手
- [ ] 每个操作都有明确的提示和反馈
- [ ] 错误提示友好，提供解决方案
- [ ] 支持示例数据一键填充

### 6.2 反馈及时性

- [ ] 上传文件后 10 秒内完成解析
- [ ] 每道题提交后 5 秒内显示评分
- [ ] 面试结束后 30 秒内生成报告
- [ ] 所有操作都有加载动画和进度提示

### 6.3 容错性

- [ ] 支持中途保存，下次继续
- [ ] 支持跳过题目，不影响后续流程
- [ ] 支持重新回答（覆盖之前的答案）
- [ ] 网络中断后自动重连，不丢失数据

### 6.4 可访问性

- [ ] 支持键盘快捷键（Enter 提交，Esc 取消）
- [ ] 支持移动端响应式布局
- [ ] 文字大小可调节
- [ ] 配色符合 WCAG 2.1 AA 标准

### 6.5 性能

- [ ] 页面加载时间 < 2 秒
- [ ] 评分响应时间 < 5 秒
- [ ] 报告生成时间 < 30 秒
- [ ] 支持 100+ 并发用户

## 七、成功指标

### 7.1 用户行为指标

- **激活率** — 注册后完成第一次模拟面试的比例 > 60%
- **完成率** — 开始面试后完成全部 4 个部分的比例 > 80%
- **留存率** — 7 日留存 > 30%，30 日留存 > 15%
- **复购率** — 完成第一次面试后再次使用的比例 > 50%

### 7.2 产品质量指标

- **评分准确性** — 用户对评分的认可度 > 70%（通过问卷调查）
- **建议有效性** — 用户认为建议有帮助的比例 > 80%
- **系统稳定性** — 可用性 > 99%，错误率 < 1%

### 7.3 商业指标

- **获客成本** — CAC < ¥50（通过 SEO + 社区推广）
- **用户价值** — LTV > ¥200（假设付费转化率 10%，客单价 ¥200）
- **投资回报** — LTV/CAC > 4

## 八、风险与缓解

### 8.1 技术风险

**风险：** OpenAI GPT-5.3-codex 评分不准确，用户不信任
**缓解：**
- 建立题库 + 参考答案，提高评分一致性
- 提供"不满意评分"反馈入口，人工复核
- 逐步积累用户反馈，优化 Prompt

### 8.2 用户体验风险

**风险：** 用户觉得题目太难或太简单
**缓解：**
- 根据用户学历和简历技能调整难度
- 提供难度选择（简单/中等/困难）
- 收集用户反馈，动态调整题库

### 8.3 商业风险

**风险：** 用户不愿意付费
**缓解：**
- 免费提供 1 次完整模拟面试（体验价值）
- 付费解锁无限次数 + 历史记录对比 + 专项训练
- 提供"面试通过返现"激励（通过面试后返还费用）
