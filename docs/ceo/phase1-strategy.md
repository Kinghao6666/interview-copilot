# Phase 1 战略决策 — AI 校招面试助手

**决策人：** CEO (Bezos)
**日期：** 2026-03-04
**决策类型：** MVP 范围确认 + Pre-Mortem 分析 + 成本控制策略

---

## 一、战略判断：这个项目值得做吗？

### ✅ 做的理由

1. **用户需求真实存在**
   - 校招求职者普遍缺乏面试练习机会
   - 现有模拟面试成本高（付费课程 ¥500-2000）或质量差（通用 AI 聊天）
   - 目标用户明确：本科/研究生计算机专业应届生

2. **简历价值明确**
   - 展示全栈能力（前端 + 后端 + LLM 集成 + 云部署）
   - 有真实用户场景，不是玩具项目
   - 可量化成果：解析准确率、评分维度、用户完成率

3. **技术栈成熟**
   - Next.js + FastAPI + Supabase + Cloudflare 都是成熟技术
   - OpenAI GPT-5.3-codex 成本可控
   - 部署简单（Cloudflare 免费额度足够 MVP）

### ⚠️ 风险点

1. **这不是一个能赚钱的产品**
   - 校招求职者付费意愿低（学生群体）
   - 竞品多（牛客、LeetCode、各种 AI 面试助手）
   - 市场规模小（仅限中国校招季，3-6 月）

2. **但这是一个好的简历项目**
   - 目标不是赚钱，是展示技术能力
   - 重点是"做出来" + "能演示" + "有亮点"
   - 投入产出比合理：4-6 周开发，换一个拿得出手的项目

**最终判断：继续做，但明确目标是简历项目，不是商业产品。**

## 三、Pre-Mortem 分析：假设项目失败了

**场景：现在是 2026 年 5 月，项目已经失败。回顾失败原因：**

### 失败模式 1：LLM 评分不可信，用户觉得是"玩具"

**症状：**
- 用户反馈："AI 给的分数不准，随便答都能 80 分"
- 评分标准不透明，用户不知道为什么扣分
- 参考答案质量差，照抄网上的标准答案

**根本原因：**
- Prompt 设计不够严谨，没有结构化约束
- 缺少评分标准的可解释性（只给分数，不给理由）
- 没有人工验证前 50 次面试结果，盲目上线

**预防措施：**
- ✅ 使用 JSON Schema 约束 LLM 输出格式
- ✅ 评分必须包含：分数 + 扣分原因 + 改进建议（3 部分）
- ✅ 人工抽查前 50 次面试，调整 prompt 直到准确率 > 80%
- ✅ 在 UI 上明确标注"仅供参考，不代表真实面试结果"

### 失败模式 2：API 成本失控，开发阶段就烧掉 ¥500+

**症状：**
- OpenAI GPT-5.3-codex 调用量暴增，每天几百次
- 开发阶段频繁测试，每次测试都调用 API
- 没有缓存机制，相同问题重复调用

**根本原因：**
- 没有设置 API 调用上限
- 开发环境和生产环境共用一个 API key
- 缺少成本监控，发现时已经超支

**预防措施：**
- ✅ 开发阶段使用 mock 数据，减少真实 API 调用
- ✅ 设置每日 API 调用上限（开发 50 次/天，生产 200 次/天）
- ✅ 实现缓存机制：相同 JD + 简历 → 缓存解析结果 24 小时
- ✅ 每周检查 OpenAI GPT-5.3-codex 账单，超过 ¥100/月立即暂停
- ✅ 使用 GPT-5.3-codex（性价比高）

### 失败模式 3：项目做了 6 周还没上线，错过校招季

**症状：**
- M1 拖了 2 周，M2 拖了 3 周，M3 遥遥无期
- 功能越做越多，UI 越改越复杂
- 团队陷入"完美主义陷阱"，不敢发布

**根本原因：**
- 没有严格的时间盒（time-boxing）
- 功能蔓延（feature creep），不断加新需求
- 缺少"可演示"的中间里程碑

**预防措施：**
- ✅ 严格执行 1 周 M1、2 周 M2、1 周 M3 的时间表
- ✅ M1 必须有可演示的 Demo（哪怕只有 3 个硬编码问题）
- ✅ 每周五团队复盘，砍掉本周未完成的功能
- ✅ 优先"能跑" > "好看" > "完美"
- ✅ 4 月 15 日前必须上线，否则项目终止

## 四、成本控制策略

### 1. OpenAI GPT-5.3-codex 成本估算

**假设：**
- 单次面试：解析（1 次）+ 生成问题（1 次）+ 评分（6 次）+ 报告（1 次）= 9 次 API 调用
- 平均每次调用：输入 500 tokens + 输出 300 tokens = 800 tokens
- GPT-5.3-codex 价格：¥0.008/1K tokens（输入+输出）
- 单次面试成本：9 × 800 × 0.008 / 1000 = ¥0.058

**MVP 阶段预算（4-6 周）：**
- 开发测试：50 次面试 × ¥0.058 = ¥2.9
- 小范围推广：100 次面试 × ¥0.058 = ¥5.8
- **总预算：¥10（含缓冲）**

**成本控制措施：**
- ✅ 开发阶段优先使用 mock 数据
- ✅ 实现缓存：相同 JD 不重复解析
- ✅ 设置每日调用上限：开发 50 次/天，生产 200 次/天
- ✅ 每周检查账单，超过 ¥10/月立即优化

### 2. Supabase 存储成本

**免费额度：**
- 数据库：500 MB（足够存储 1000+ 面试记录）
- 认证：50,000 MAU（月活用户，远超 MVP 需求）
- 存储：1 GB（足够存储 500+ 简历 PDF）

**MVP 阶段：完全免费**

### 3. Cloudflare R2 存储成本

**免费额度：**
- 存储：10 GB/月
- Class A 操作（写入）：1M 次/月
- Class B 操作（读取）：10M 次/月

**MVP 阶段预算：**
- 简历 PDF 存储：100 个 × 2 MB = 200 MB
- 报告 PDF 存储：100 个 × 500 KB = 50 MB
- **总存储：< 1 GB，完全免费**

### 4. Cloudflare Pages/Workers 成本

**免费额度：**
- Pages：无限请求（静态资源）
- Workers：100,000 次请求/天

**MVP 阶段：完全免费**

### 总成本预估

| 项目 | MVP 阶段（4-6 周） | 备注 |
|------|-------------------|------|
| OpenAI GPT-5.3-codex | ¥10 | 主要成本 |
| Supabase | ¥0 | 免费额度足够 |
| Cloudflare R2 | ¥0 | 免费额度足够 |
| Cloudflare Pages/Workers | ¥0 | 免费额度足够 |
| **总计** | **¥10** | 可接受 |

**结论：成本可控，继续推进。**
